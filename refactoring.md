# Refactoring Plan — Listen

Философию не ломаем: **menu-bar иконка, ноль окон (кроме одного загрузчика модели),
ноль аккаунтов, всё офлайн**. Настройки добавляем, но только те три, что перечислены
ниже, — меню и есть весь UI.

Факты, проверенные экспериментально (2026-08-21):
- ✅ `nemo-speech serve` грузит модель за **~8 с** (Metal, Q8_0) — окно готовности 120 с избыточно, но безопасно.
- ✅ эндпоинт `/v1/audio/transcriptions` принимает поле `language` (проверено: `ru-RU` → 200 OK).
- ✅ дефолтный порт бинаря — 8080, флаги `--host/--port` есть (см. `--help`).

## Phase 1 — Убрать конфликт порта 8080

**Проблема:** `config.py:22` — фиксированный `PORT=8080`. Занят → подпроцесс умирает →
`FAILED` без фолбэка. Плюс неявный побочный эффект: именно фиксированный порт сейчас
«защищает» от запуска двух копий приложения.

**Изменения:**

1. `listen/server.py` — новый метод подбора порта:
   ```python
   def _free_port() -> int:
       s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
       s.bind(("127.0.0.1", 0))
       port = s.getsockname()[1]
       s.close()
       return port
   ```
   Порт выбирается при каждом старте, хранится в `self._port`, используется в
   `--port`, в `/ready` и в `transcribe()`. `config.PORT` — удалить; env `LISTEN_PORT`
   оставить только как debug-override (если задан — использовать как есть, для ручной диагностики).
2. **Ретрай при редкой гонке** (между `close()` и биндом бинаря порт могли занять):
   если подпроцесс вышел до готовности — взять новый порт и попробовать ещё раз (макс. 3 попытки, потом `FAILED`).
3. **Single-instance lock — обязателен** (следствие ухода от фиксированного порта):
   `~/.listen/app.lock` + `fcntl.flock(LOCK_NB)`. Вторая копия: запись в лог + тихий выход.
   `flock` освобождается автоматически даже при SIGKILL — pid-файл не нужен.
4. **Чистка осиротевшего сервера:** при SIGKILL родителя `nemo-speech` остается жить
   (~1 ГБ RAM). Писать pid подпроцесса в `~/.listen/server.pid`; при старте, если pid
   жив и cmdline содержит `nemo-speech serve` — убить.

**Приёмка:** `lsof -iTCP -sTCP:LISTEN` показывает случайный высокий порт у
`nemo-speech`, только 127.0.0.1; два запуска подряд → второй тихо умирает;
`kill -9` приложения + повторный запуск → старый сервер убит.

## Phase 2 — Явные пермишены с подсказками

**Проблема сейчас:**
- Без Accessibility `hotkey.start()` бросает RuntimeError в `app.run()` (`app.py:137`)
  → **приложение падает** на первом запуске; пермишен нужно выдать и перезапустить вручную.
- Отказ в микрофоне виден только как краткая ⚠ иконка + строка в логе.
- `__main__.py:15-41` — проверка AX живёт в точке входа, переиспользовать нельзя.

**Изменения:**

1. Новый модуль `listen/permissions.py`:
   - `accessibility_trusted(prompt: bool) -> bool` — переезд `_ax_trusted` из `__main__.py`;
   - `open_accessibility_settings()` / `open_microphone_settings()` — `open` нужного
     `x-apple.systempreferences:` URL (микрофонный: `…Privacy_Microphone`);
   - `mic_prompt_and_check() -> bool` — открыть `InputStream` на 0.1 с: macOS в этот
     момент показывает системный диалог; PortAudio-ошибка = «отказано».
     (Статус TCC-микрофона нельзя запросить API — только пробным открытием.)
2. `app.run()` **не создает event tap, пока AX не выдан**: вместо падения — состояние
   `NEEDS_AX`. Основной цикл раз в секунду опрашивает `AXIsProcessTrusted()`; как только
   выдан — tap создается на лету, **без перезапуска** (это главное UX-исправление).
3. Меню в этом состоянии сверху показывает динамический пункт:
   `⚠ Grant Accessibility…` → открывает панель настроек. Иконка в баре — ⚠.
4. Ошибка микрофона (PortAudio error при старте записи) → пункт меню
   `⚠ Grant Microphone Access…` + ⚠ иконка до успешной записи.
5. Подсказка «почему»: tooltip иконки и заголовки пунктов одним предложение объясняют
   зачем («нужно для хоткея и вставки текста», «нужно для записи речи») — без модальных
   окон и туториалов.

**Приёмка:** свежая система, без пермишенов → приложение живет, ⚠ в баре, меню
предлагает выдать оба; после выдачи AX в System Settings хоткей начинает работать без
перезапуска; отказ в микрофоне → понятный пункт меню.

## Phase 3 — Чистая архитектура

**Проблемы:** `app.py` (300 строк) смешивает рисование иконок, меню, пульсацию,
состояние записи, вставку; «состояние приложения» размазано по `server.state` +
`_recording` + juggling иконок; логика хоткея зашита под правый Option.

**Целевая структура:**

```
listen/
├── __main__.py      # только вход: лог, lock, настройки, запуск App
├── app.py           # App: машина состояний + wiring (~150 строк)
├── state.py         # enum AppState: NEEDS_AX | DOWNLOADING | LOADING | READY |
│                    #                RECORDING | TRANSCRIBING | MIC_DENIED | ERROR
├── icons.py         # _mic/_warn/_red_dot + сборка кэша (из app.py)
├── menu.py          # построение и обновление NSMenu (см. Phase 4)
├── settings.py      # ~/.listen/settings.json: load/save (атомарно: tmp+rename)
├── permissions.py   # Phase 2
├── hotkey.py        # обобщённый хоткей (Phase 4)
├── audio.py         # как есть + tempfile + безопасный stop()
├── paste.py         # + защита changeCount при restore
├── server.py        # Phase 1
├── firstrun.py      # заменить устаревшие NSTitledWindowMask на styleMask-enum
└── autostart.py     # как есть (launchctl-путь рабочий; SMAppService не даёт
                     #  выигрыша при наличии dev-режима без бандла)
```

Ключевые правила:

1. **Один источник правды о состоянии** — `AppState` + метод `_apply_state()`:
   иконка, tooltip и меню выводятся из состояния, а не выставляются вразнобой
   (сегодня `_set_icon` зовется из 7 мест).
2. **Пульсация** — деталь иконки: `icons.py` сам держит NSTimer, `app.py` только
   `icons.set_recording(True/False)`.
3. **`transcribe_and_paste`**: результат/ошибка возвращаются в главный поток через
   `performSelectorOnMainThread` (уже так) — сохранить.
4. **Тесты (сейчас ноль):** `pytest` для чистой логики без GUI:
   машина состояний хоткея (выделить в чистую функцию `decide(event)->Action`),
   `_free_port`, `_multipart`, `settings.load/save` (roundtrip, битый JSON → дефолты),
   `config.resolve_model_path`. GUI не тестируем — PyObjC в CI не нужен.
5. Мелочи: `audio.stop()` без `start()` не должен ронять (assert → безопасный
   возврат); WAV — `tempfile` вместо фиксированного `/tmp/listenit_recording.wav`;
   подписи потоков (кто на каком треде) — комментариями, это частый источник багов в PyObjC.

## Phase 4 — Меню: hotkey / language / autostart

Целевое меню (лаконично — 4 сущности, никаких «Preferences…»-окон):

```
        Hotkey: Right Option   ▸
        Language: Auto         ▸
        ✓ Start at Login
        ─────────────────────────
        Quit                    ⌘Q
```

Динамические пункты `⚠ Grant …` добавляются сверху только когда пермишена нет (Phase 2).

**4.1. Hotkey (по умолчанию — правый Option)**

- `settings.json`: `{"hotkey": {"keycode": 61, "is_modifier": true, "flags": 0}, …}`
  (61 = `kVK_RightOption`).
- `hotkey.py`: обобщить — модификаторные клавиши сохраняют семантику «нажал-отпустил
  в одиночку» (существующий код), обычные клавиши — семантика «нажатие = toggle»
  (keyDown без ожидания отпускания). Логику решения выделить в чистую функцию → тестируется.
- Захват нового хоткея **без окна**: пункт «Press new key…» переводит tap в режим
  capture — заголовок пункта меняется на `Press any key… (Esc = cancel)`, следующий
  keyDown/flagsChanged становится новым хоткеем. Ноль новых окон — соответствует
  философии. Esc = отмена. Записывать keycode+модификаторы.
- Подменю: `Change…`, `Reset to Default`. Отображение имени клавиши — таблица
  keycode→символ для популярных + fallback "Key 63".

**4.2. Language (по умолчанию — Auto)**

- Значение `null` (Auto) или локаль. Передавать в `Server.transcribe(wav, language)`
  — поле формы уже реализовано в `server.py:161-166`, эндпоинт принимает (✅ проверено).
- Список — из карточки модели, сгруппировать по готовности (транскрипция → broad):
  - **19 готовых:** en-US, en-GB, es-US, es-ES, fr-FR, fr-CA, it-IT, pt-BR, pt-PT,
    nl-NL, de-DE, tr-TR, ru-RU, ar-AR, hi-IN, ja-JP, ko-KR, vi-VN, uk-UA
  - **13 broad-coverage:** pl-PL, sv-SE, cs-CZ, nb-NO, da-DK, bg-BG, fi-FI, hr-HR,
    sk-SK, zh-CN, hu-HU, ro-RO, et-EE
  - 8 «adaptation-ready» (нужен fine-tuning) — **в меню не включать**.
- Подменю: `Auto` (галка по умолчанию) → 19 готовых → разделитель → 13 broad.
  Человеческие имена языков hardcoded (`"ru-RU": "Russian"`), сортировка по имени.

**4.3. Start at Login (чекбокс, по умолчанию выкл)**

- Уже реализовано (`autostart.py`) — оставить механику LaunchAgent, состояние
  пункта обновлять в `menuWillOpen` (сейчас проверяется один раз при старте, `app.py:180`).

**Приёмка:** смена хоткея работает на лету; смена языка видна в транскрипции
(продиктовать русское слово с `ru-RU` и с `Auto`); галка автостарта переживает
перезапуск; `settings.json` читается при старте, битый файл → дефолты + лог.

### Рекомендации (вне фаз, по приоритету)

1. **Подпись и нотаризация.** Сейчас DMG подписан ad-hoc → у пользователей Homebrew
   Gatekeeper ругается, а **Accessibility-пермишен слетает при каждой пересборке**
   (TCC привязан к сигнатуре) — это источник «после обновления снова просит
   разрешения». Минимум: стабильный self-signed identity для локальных сборок;
   правильно: Developer ID + `codesign --options runtime` + `xcrun notarytool` в
   `make-dmg.sh`.
2. **sha256 модели** после докачки (данные уже в `model-index.json`) — дешево, спасает от труднодиагностируемых падений.
3. **Буфер обмена:** перед restore сравнивать `pb.changeCount()` с записанным при
   вставке; если пользователь успел скопировать своё — не затирать.
4. **Ошибки дольше:** ⚠-иконку держать до следующего успешного действия (не 1.5 с),
   последняя ошибка — строкой в меню («Last error: server failed») + пункт «Open Log».
5. **Idle-unload сервера (опционально):** модель держит ~1 ГБ RAM. Старт ~8 с (✅) —
   можно выгружать после 10 мин простоя и лениво грузить при первом нажатии. Решение
   продуктовой trade-off «8 с ожидания первой фразы vs 1 ГБ RAM» — оставить на усмотрение, по умолчанию НЕ делать.
6. **README:** обещание «no settings, no modes» перестанет быть буквальным — обновить
   формулировку («две настройки, ноль окон») вместе с Phase 4.

### Рекомендации по UI (лаконичность)

- **Меню = весь UI.** Никаких Preferences-окон, About-панелей, onboarding-туториалов.
  Три пункта + Quit — это потолок.
- **Значение видно без открытия подменю** («Language: Auto ▸») — пользователь видит
  текущее состояние мгновенно, это нативный паттерн macOS.
- **Tooltips на иконке** (почти бесплатно, большая отдача): `Ready — press right
  Option`, `Loading model…`, `Recording…`, `Transcribing…`, `Accessibility required —
  click for details`. Иконка без подписи молчит — tooltip единственное место, где
  можно объяснить состояние.
- **Захват хоткея внутри пункта меню**, без модального окна (см. 4.1) — согласуется с
  «единственное окно в приложении — загрузчик модели».
- ⚠-пункты пермишенов появляются **только** когда чего-то не хватает и исчезают после
  выдачи — меню у чистой системы из 4 строк.
- Пульс красным при записи оставить (есть Reduce Motion-ветка — правильно), не
  добавлять звуки/уведомления — приложение должно быть «quiet utility».
